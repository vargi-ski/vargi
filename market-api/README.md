# VARGI Market API

Backend барахолки стаи ВАРГИ.

## Отправка и проверка

- `npm ci && npm test` — изолированные регрессионные тесты без боевых секретов и Telegram-отправок.
- `/submit`: до 6 фото по 8 МиБ, суммарно до 24 МиБ; JPEG/PNG/WebP до 64 Мп, преобразование в JPEG до 1800 px. Фронтенд принимает исходники до 15 МиБ и уменьшает их перед отправкой; HEIC до 8 МиБ.
- Сервер проверяет обязательные поля и согласие `board-submit-2026-10-05`. Категория, контакт и форматированная цена формируются из проверенных значений.
- UUID `requestId` + хеш содержимого записываются вместе с заявкой. Повтор возвращает прежний ID, изменённое содержимое с тем же ключом — 409. Конкурентная блокировка рассчитана на текущую одну реплику сервиса; перед масштабированием нужен общий атомарный механизм.
- Тайм-аут браузерной отправки — 120 секунд. При ошибке форма и фото остаются во вкладке, повтор использует прежний ключ. Лимит 6 попыток за 15 минут сохраняется; 429 содержит `retryAfter`.
- `telegram_notify_sent id=…` подтверждает принятие уведомления Telegram API; это не подтверждение прочтения человеком. Заявка сохраняется независимо от доступности Telegram.

## Хранение

- На странице подачи есть проверка доступности сервера из браузера и диагностика OFFLINE / NETWORK / TIMEOUT / RESPONSE / RATE_LIMIT / SERVER с временем и версией формы. HTTP-ответы дополнительно содержат `X-Request-Id`, связанный с журналом прихода, ответа или обрыва загрузки. Содержимое заявки и контакты в эти журналы не попадают.
- Черновик, подготовленные фото и ключ повтора сохраняются в IndexedDB этого браузера. Восстановление предлагается явно, после успешной отправки черновик удаляется. Черновики старше 7 дней удаляются при следующем открытии формы. Запрет/переполнение/зависание хранилища не блокирует отправку; пользователь видит предупреждение.
- `/health` проверяет запись и чтение в каталоге заявок; при проблеме возвращает 503 вместо ложного `ok: true`.
- GitHub Actions `Forms regression checks` запускает проверки при изменениях формы/API. Это проверка регрессий, не блокировка публикации GitHub Pages и не мониторинг доступности из всех сетей.
- Публичный API пока использует Railway service domain. Переключение на `market.варги-стая.рф` допустимо только после подтверждения DNS, выдачи валидного TLS и проверки CORS. Неработающий TLS нельзя обходить или объявлять резервным каналом.

- заявки и фотографии: постоянный Railway volume `/data/submissions`;
- хеш пароля администратора: `/data/admin-auth.json`;
- удалённые объявления сначала попадают в статус `trash` и физически очищаются через 30 дней.

## Резервные копии

Сервис создаёт ежедневный архив volume-данных в приватный Railway Bucket и хранит последние 14 дней.
Ручной backup доступен из админ-панели.

Переменные:
- `BACKUP_S3_ENDPOINT`
- `BACKUP_S3_REGION`
- `BACKUP_S3_BUCKET`
- `BACKUP_S3_ACCESS_KEY_ID`
- `BACKUP_S3_SECRET_ACCESS_KEY`

## Уведомления о кемпе из Яндекс Форм

Используется существующий Telegram-бот и уже подключённый чат из `/data/telegram-notify.json`. Переподключать бота для кемпа не нужно. Email-интеграция Яндекс Форм и заявки барахолки работают независимо.

- Задать `CAMP_FORM_WEBHOOK_TOKEN` — отдельный случайный секрет длиной не менее 32 символов, только в Railway Variables и закрытой настройке интеграции Яндекс Форм.
- В интеграции формы `6aacf2a849af472ed76c9d3d` выбрать HTTP POST на `https://<домен API>/integrations/yandex/camp`; заголовки `Content-Type: application/json` и `Authorization: Bearer <CAMP_FORM_WEBHOOK_TOKEN>`.
- Тело: `{"form_id":"6aacf2a849af472ed76c9d3d","response_id":"<переменная ID ответа>","camp":"<переменная GET-параметр vargi_camp>"}`. Вставлять переменные средствами Яндекс Форм, с JSON-экранированием; не передавать имя, email, сообщение или все ответы.
- Страница кемпа добавляет `vargi_camp=first-snow-2026` в ссылку на форму. Если параметр пустой или другой, webhook отвечает `200 ignored` и ничего не отправляет. Остальные поля и неизвестная форма отклоняются. `response_id` — строка 1–128 символов из букв ASCII, цифр, `_` и `-`.
- Это серверный endpoint: запросы с `Origin` отклоняются, секрет не добавляется в браузерный код. `GET /integrations/yandex/camp/status` с тем же Bearer возвращает только наличие настройки, подключение чата, username бота и подпись чата; токен и chat ID не раскрываются.

До HTTP 202 webhook записывает задание в постоянную очередь `/data/camp-notifications` с синхронизацией файла и каталога. Telegram вызывается в фоне, поэтому его таймаут 7 секунд не задерживает ответ Яндексу с лимитом ожидания 5 секунд. Очередь восстанавливается при старте, временные ошибки повторяются с интервалом от 30 секунд до часа. При штатной работе новые записи подбираются сразу или в пределах 15 секунд. В сообщении только фиксированное уведомление о кемпе и кнопка на закрытый раздел ответов Яндекс Форм; контакты и свободный текст не пересылаются и не сохраняются здесь.

Дедупликация по паре ID формы + ID ответа переживает рестарт. Она рассчитана на одну реплику с постоянным volume. Как у любой очереди без общей транзакции с Telegram, при аварии строго между принятием сообщения Telegram и фиксацией `sent` возможен повтор уведомления. Успешные записи дедупликации не удаляются и входят в существующий ежедневный backup. Логи содержат только хеш ID задания и этап доставки.

Контроль настройки: проверить защищённый `/status`, отправить один помеченный тест через форму, затем проверить выполненную HTTP-интеграцию в Яндексе и `camp_telegram_sent` в журнале сервера. Принятие Telegram API не подтверждает прочтение сообщения. Яндекс документирует IPv6 для HTTP-интеграции; доступность адреса нужно подтвердить реальным тестом формы. Локальные тесты работают только с синтетическими данными и подставной функцией отправки, без боевого Telegram.

## Уведомления о заказах магазина из Яндекс Форм

Форма магазина `6aad189e84227c2dd4dbd7a6` отправляет уведомление через существующего Telegram-бота в уже подключённый чат из `/data/telegram-notify.json`. Это отдельный канал от уведомлений кемпа и барахолки; почтовая интеграция формы сохраняется. Уведомляются все успешно отправленные заказы экипировки, включая предзаказы.

- Задать отдельный `SHOP_FORM_WEBHOOK_TOKEN` — случайный секрет длиной не менее 32 символов, только в Railway Variables и закрытых настройках формы. Не использовать токен кемпа или токен Telegram-бота.
- Для формы магазина добавить действие HTTP POST на `https://market.xn----7sbbfg4a6clj5k.xn--p1ai/integrations/yandex/shop` с заголовками `Content-Type: application/json` и `Authorization: Bearer <SHOP_FORM_WEBHOOK_TOKEN>`.
- Тело: `{"form_id":"6aad189e84227c2dd4dbd7a6","response_id":"<переменная ID ответа>"}`. ID ответа вставляется средствами Яндекс Форм с JSON-экранированием. Имя, контакты, состав заказа, мерки и свободный текст не передаются. Неизвестные поля, другая форма и невалидный ID отклоняются.
- Запросы с `Origin` отклоняются: это интеграция сервер–сервер, секрет не должен находиться в браузерном коде сайта.
- `GET /integrations/yandex/shop/status` с тем же Bearer возвращает наличие токена бота, подключение получателя, доступность бота через `getMe` и агрегаты очереди: `pending`, `sent`, `unreadable`, `lastSentAt`. Секреты, chat ID и ID ответов не возвращаются. Успех `getMe` не подтверждает доставку уведомления.

До HTTP 202 задание записывается с синхронизацией файла и каталога в постоянную очередь `/data/shop-notifications`. Telegram вызывается в фоне, чтобы его таймаут не задерживал ответ Яндекс Формам. После временной ошибки доставка повторяется с интервалом от 30 секунд до часа; очередь восстанавливается после рестарта. Сообщение содержит только «Новый заказ экипировки ВАРГИ» и кнопку «Открыть заказы магазина» на закрытый раздел ответов формы.

Дедупликация по ID формы и ответа переживает рестарт и рассчитана на одну реплику с постоянным volume. Сбой строго между принятием сообщения Telegram и записью `sent` может привести к повторному уведомлению. Записи входят в ежедневный backup. В журнале только хеш задания и события `shop_outbox_queued`, `shop_telegram_sent`, `shop_telegram_retry`; ошибки провайдера и содержимое заявки не журналируются.

Для проверки: защищённый статус, выполненная HTTP-интеграция в Яндекс Формах, затем `shop_telegram_sent` в журнале. Статус HTTP 202 означает приём в очередь; только `shop_telegram_sent` означает принятие сообщения Telegram API. Старые ответы автоматически не пересылаются. Локальные тесты используют синтетические ID и подставную отправку, без реальных заявок и сообщений.
