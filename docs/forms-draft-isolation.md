# Изоляция черновиков заявок ВАРГИ

Дата: 20.11.2026

## Причина и воспроизведение

Страницы вступления, контактов и кемпа используют одну Яндекс Форму `6aacf2a849af472ed76c9d3d`. Браузерный виджет сохраняет незавершённые ответы по идентификатору формы. Пустой GET-параметр `message=` не перекрывает сохранённый непустой ответ.

В браузере воспроизведено: открыть `/contact/#message=...` с синтетическим объявлением, затем `/join/` — текст объявления остаётся в сообщении вступления. Настройка «Подставлять в форму предыдущие ответы пользователя» при этом выключена; значения по умолчанию у вопросов не заданы. Это смешивание локальных черновиков разных сценариев, а не подтверждённая отправка чужой заявки.

Проверен публичный код действующего виджета Яндекса: https://yastatic-net.ru/s3/cloud/forms/static/freeze/js/index.fa4bec56.js . Параметр `form:cache_key` задаёт отдельное пространство черновика; допустимое значение — 3–50 латинских букв, цифр, подчёркиваний и дефисов. Общее описание настройки предыдущих ответов: https://yandex.ru/support/forms/ru/refilling .

## Исправление

| Сценарий | form:cache_key |
| --- | --- |
| Вступление | vargi-join-v1 |
| Обычное обращение | vargi-contact-v1 |
| Обращение с перенесённым текстом, включая объявление | vargi-contact-prefill-v1 |
| Кемп «Вкатка 2026» | vargi-camp-first-snow-2026-v1 |

Одинаковые ключи используются у iframe и ссылки «Открыть отдельно». Статические ссылки также изолированы, включая работу без JavaScript. Служебные маршруты webhook и идентификатор Яндекс Формы сохранены. Пользовательские параметры не могут заменить ключ. Не используются пробелы или фиктивный текст вместо обязательного сообщения; контакты не записываются в хранилище самого сайта.

Собственная незавершённая анкета одного сценария сохраняется при возвращении. Чужой сценарий её не заполняет. Не требуется удалять cookies или черновики пользователя.

Реальные контакты посетителей не использовались.

## Сопровождение

`form:cache_key` проверен на действующем виджете; при существенном обновлении Яндекс Форм повторить браузерный сценарий «объявление → вступление → контакты». Не смешивать эти ключи при будущих правках. Идентификаторы заявок, номера ответов Telegram и состояние сервера не заменяют проверку фактической доставки новой заявки.

## Разделение вступления и обращений

В Яндекс Формах для вопроса «Тема обращения» (`135899672`, GET-ключ `answer_choices_96193`) настроено условие показа: «Маршрут анкеты вступления» (`145572498`, GET-ключ `vargi_join`) **не равно** `1`.

На `/join/` посетитель видит формат участия, контакты, рассказ о себе и согласие; списка общих тем нет. Тема «Вступление в стаю» задаётся служебно через существующий GET-параметр. На `/contact/` список тем виден, а выбор основного/расширенного состава или сообщества отсутствует. Проверено на опубликованной форме в браузере в обоих направлениях. Условие хранится у провайдера формы; один только откат GitHub его не отменит. Старые вопросы и ответы не удалялись.

Страница контактов оформлена как «Вопросы и обращения»; на обеих страницах есть ссылка на другой сценарий. Новая заявка для проверки после изменения показа не отправлялась: разрешённый единичный тест доставки выполнен до этой правки интерфейса; webhook и очередь уведомлений не изменялись.
